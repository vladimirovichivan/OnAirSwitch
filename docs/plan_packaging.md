## 1. Цель и результат

Собрать из текущего проекта автономный установщик, который ставится на чужой ПК
без Python, git и прав администратора, и пройти приёмку на Windows 11 и Windows 10.

Результат фазы — артефакты:

| Артефакт | Назначение |
|---|---|
| `OnAirLamp-Setup-1.0.0.exe` | установщик per-user, ярлыки, автозапуск |
| `OnAirLamp-1.0.0-win64.zip` | портативная копия того же (для проверки и «попробовать») |
| `SHA256SUMS.txt` | хеши — чтобы получатель мог проверить файл |
| `INSTALL.md` (PDF/печать) | инструкция со скриншотами Tuya |
| `SUPPORT.md` | что прислать, если не работает |

Не входит: автообновление, GUI, DPAPI, изменение семантики определения встреч,
подпись кода (обсуждается отдельно).

## 3. Целевая структура поставки

```
%LOCALAPPDATA%\Programs\OnAirLamp\
├── python\                 эмбеддированный Python 3.12 (python.exe, pythonw.exe)
├── vendor\                 зависимости из requirements.txt (без pip)
├── app\
│   ├── scripts\meetings\   скрипты как есть + build.json
│   │   └── icons\          lamp-on.png, lamp-off.png (PNG с альфой)
│   ├── data\work\meetings\ создаётся при первом запуске
│   └── secrets\            создаётся мастером
├── start.vbs               один автозапуск: три процесса скрыто
├── setup.cmd               мастер первой настройки
├── verify.cmd              проверка розетки и связи
├── report.cmd              zip журналов без секретов
├── restart.ps1, stop.ps1   перезапуск и полная остановка процессов
└── licenses\               Python (PSF), tinytuya (MIT), pystray (LGPL-3.0), Pillow (MIT-CMU)
```

Структура повторяет репозиторий, поэтому `REPO_ROOT` (`SCRIPT_DIR.parent.parent`)
в скриптах работает без изменений.

### Фаза 2. Правки для автономности — выполнено 16.11.2026

Три изменения, согласованные решением D-63. Сделаны **в этом проекте**:

1. `tuya_setup.py --verify`: UDP-поиск адреса → чтение DP → переключение →
   повторное чтение → возврат в исходное состояние. Печатает имя, адрес,
   протокол, DP и состояние; ключи не печатает.
2. UDP-поиск адреса по `dev_id`: в `tuya_setup.py` (шаг мастера) и как резерв в
   `plug_executor.py` — если настроенный адрес не отвечает, один раз найти
   устройство и продолжить с найденным адресом; в журнал — `address rediscovered`.
   Конфиг не перезаписывать (после смены IP всё равно нужна резервация в DHCP).
3. Строка версии сборки при старте исполнителя: читать `app\build.json`
   (`version`, `built`, `commit`), если файла нет — писать `dev`.

**Техническая заметка (проверено по установленному пакету):** в `tinytuya
1.21.1` функции `deviceScan` нет — это историческое имя из документации; сканер
находится в `tinytuya.scanner` (`devices(...)`, `scan(...)`). Поэтому поиск:
`tinytuya.scanner.devices(verbose=False, color=False, poll=False,
assume_yes=True, byID=True)` и выбор по `dev_id`; поведение на живой сети
проверить. **Резервный путь** — пассивное прослушивание UDP 6666/6667/7000
(проверено 16.11.2026): объявления устройств дают адрес и `gwId`, ключи не нужны.
Каждый найденный адрес всё равно подтверждается чтением статуса.

Проверки: `--verify` на реальной розетке (переключение и возврат), dry-run
исполнителя без сети, поведение при неверном адресе, отсутствие `local_key` в
выводе.

Результат 16.11.2026:

- добавлен `app\scripts\meetings\tuya_discovery.py`: активный скан
  `tinytuya.scanner.devices(...)` + резервное пассивное прослушивание UDP
  6666/6667/7000 (только стандартная библиотека, разбор через
  `tinytuya.decrypt_udp`). На живой сети сработали оба пути;
- `tuya_setup.py`: `--verify` (поиск адреса → чтение DP → переключение →
  подтверждение → возврат исходного состояния) и UDP-поиск на шаге мастера;
  `--verify` отказывается работать во время встречи без `--force`;
- `plug_executor.py`: при молчании настроенного адреса — один поиск по `dev_id`
  (не чаще раза в 10 минут), запись `address rediscovered: <старый> -> <новый>`,
  конфиг не перезаписывается; при старте пишется версия сборки из
  `app\build.json` (нет файла — `dev`);
- проверено на устройстве: `--verify` вернул исходное состояние, exit 0; подмена
  адреса на недостижимый → `address rediscovered` и успешное чтение статуса;
  в выводе нет `local_key`, `dev_id` только маской;
- dry-run проверен изолированно (временные `--status`/`--log`): устройство не
  опрашивается, в журнал пишется `build dev` и `[dry-run]`.

**Готово:** проверка проходит на реальном устройстве, ошибки печатаются
по-русски и с действием, в выводе и журналах нет ключей.

## 5. Риски и как их снимать

| Риск | Проверка / смягчение |
|---|---|
| `cryptography`/`Pillow` не импортируются под эмбеддированным Python | проверка импортов в `build.ps1` **до** сборки установщика |
| Антивирус/SmartScreen ругаются на установщик | без подписи — предупреждение в инструкции и хеши; при жалобах обсудить сертификат |
| Два экземпляра (старая и новая копии) конфликтуют по mutex | снято 16.11.2026: автозапуск прежней копии удалён, осталась только копия OnAir Lamp |
| UDP-поиск в `tinytuya.scanner` интерактивен или печатает в stdout | проверить на живой сети; при проблемах — резервный путь на 6667 |
| Смена IP розетки | резервный поиск + совет зарезервировать адрес в DHCP |
| Права на `%LOCALAPPDATA%\Programs` | установка per-user, UAC не нужен; проверить на ПК без администратора |
| Разные версии у получателей | версия в `build.json`, журнале, отчёте и имени установщика |
| Обновления Толка/Телемоста/Zoom ломают признаки окон | поле `events.log` в отчёте; исправление — новая сборка |
| Windows 10 отличается поведением | отдельный прогон приёмки, а не «должно работать» |

## 7. Чек-лист приёмки

На каждом ПК (Windows 11 и Windows 10), человек без подсказок:

1. Установка без прав администратора; ярлыки в меню Пуск; иконка в трее после
   запуска.
2. Мастер: ввод ключей Tuya, выбор устройства, адрес найден UDP-поиском.
3. `verify`: чтение DP, переключение, возврат в исходное состояние; ключи не
   показаны.
4. Встреча в Толке: включение ≤10 с, выход — выключение ≤10 с.
5. То же для Телемоста и Zoom, включая свёрнутое плавающее окно Zoom.
6. Меню трея: «Выключить на 1 час» — лампа гаснет, по истечении срока
   возвращается автоматика.
7. Выключить роутер на 2 минуты: лампа не залипает, после возврата сети
   состояние восстанавливается само; `report.cmd` собирает архив без ключа.
8. Перезагрузка Windows: приложение стартует само, в простое лампа выключена.
9. Удаление: ярлыки и автозапуск убраны, настройки на месте, повторная установка
   работает.
10. Размер установщика и время установки приемлемы (ориентир: ≤25 МБ, ≤1 мин).
