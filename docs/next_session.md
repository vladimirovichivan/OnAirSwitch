# Промпт для следующей сессии

Скопировать целиком в новую сессию (лучше с рабочей папкой `D:\onair-lamp`).

---

Проект **OnAir Lamp**: умная розетка Tuya («лампа On air») горит, пока идёт
видеовстреча в Толке, Телемосте или Zoom. Основной проект — `D:\onair-lamp`;
Legacy по лампе больше не развивается и архивом не считается (D-64).

Разработка ведётся в ветке `main`; версия для передачи другим людям — отдельный
форк, который следует за основной веткой (D-65). Релизы — GitHub Releases,
дополнительно портативный zip.

Рабочая папка — `D:\onair-lamp`. Сначала прочитай: `README.md`,
`docs\ARCHITECTURE.md`, `docs\HISTORY.md`, `docs\plan_packaging.md`,
`docs\SUPPORT.md`.

## Фактическое состояние (16.11.2026, после фазы 1)

- Переезд закоммичен в `main`; `.venv` создан, зависимости из `requirements.txt`
  установлены, импорты и `py_compile` проходят.
- Секрет лежит в `app\secrets\tuya_plug.json` (локальная копия из Legacy,
  содержимое не печатать). `app\data\` и `app\secrets\` исключены из Git.
- Три процесса запущены из `D:\onair-lamp` (наблюдатель, исполнитель с
  `--apply`, трей); процессы Legacy остановлены.
- Фаза 1 пройдена на реальном устройстве и живых встречах: Толк, Zoom, Телемост.
  Включение 1/1/3 с, выключение 1/1/3 с; ручной режим из трея и возврат `auto`
  работают; ошибок в журналах нет.
- Автозапуск пока остаётся у Legacy: после перезагрузки поднимется старая копия.
  Переключение автозапуска — по фазе 3/6, после сборки, с отдельной проверкой
  перезагрузки.

(правки для автономности) → 3 (сборка) → 4 (приёмка) → 5 (передача).

Перед действиями проверь факты, а не полагайся на этот текст: `git status`,

## Решения, которые нельзя менять молча

- **D-55/D-61:** сверка «желаемое/фактическое», `control.json` важнее
  `state.json`, единственный клиент устройства — исполнитель, dry-run по
  умолчанию, устаревшее состояние ≠ «встречи нет».
- **D-58:** встреча определяется только окном; аудиосессия — только диагностика.
- **D-56/D-59/D-60** и исправление 16.11.2026: у Zoom шаблоны заголовков с `\b`
  (7.1 добавляет суффикс, например «Zoom Meeting 40-Minutes»); свёрнутое
  плавающее окно Zoom — встреча; настройки Телемоста — служебное окно;
  «Звонок» Телемоста — сама встреча.
- **D-62/D-63:** эмбеддированный Python 3.12.10 + Inno Setup (без PyInstaller);
  установка per-user в `%LOCALAPPDATA%\Programs\OnAirLamp` без UAC; три
  процесса; один автозапуск `HKCU\…\Run` → `start.vbs`; открытый
  `app\secrets\tuya_plug.json`; адрес розетки вручную и UDP-поиском; управление
  только меню трея; целевые ОС Windows 11 и Windows 10.
- **D-64/D-65:** код лампы живёт в `D:\onair-lamp`; Legacy не развивается;
  передача — отдельным форком за `main`; релизы GitHub Releases + zip.

## Технические факты

- `tinytuya 1.21.1`: функции `deviceScan` нет, сканер — `tinytuya.scanner.devices(...)`;
  резервный путь — классический UDP-запрос на порт 6667 (проверен 13.11.2026,
  ответили `192.168.111.124` и `.60`), адрес подтверждать чтением статуса и
  сверкой `gwId` с `dev_id`.
- Mutex: `Local\LegacyPlugExecutor`, `Local\LegacyPlugTray` — два экземпляра
  одновременно не запустятся; общий для Legacy и нового проекта.
- Корень вычисляется как `SCRIPT_DIR.parent.parent`, поэтому в проекте это
  `D:\onair-lamp\app`, данные — `app\data\work\meetings\`, конфиг —
  `app\secrets\tuya_plug.json`. Установка обязана повторять раскладку
  `app\scripts\meetings\…`.
- Устройство: протокол 3.3, переключатель DP 1; адрес задаётся в
  `tuya_plug.json`.
- `scripts\setup-dev.ps1` должен оставаться в UTF-8 **с BOM**, иначе Windows
  PowerShell 5.1 не разбирает кириллицу.
- Оценка оставшихся работ по плану — ≈2–2,5 рабочих дня.

## Правила

- Секреты (`local_key`, Access Secret) не печатать, не передавать в модель, логи
  и документы; проверять только факт наличия.
- Не менять `D:\Legacy` и его автозапуск без отдельного разрешения; не трогать
  данные и настройки получателей.
- Не устанавливать пакеты и не делать коммиты без разрешения.
- Не выдавать план за результат: «работает» — только после проверки на реальном
  устройстве и живой встрече.
- После значимых изменений обновлять документы проекта (`plan_packaging.md` —
  статусы фаз, `HISTORY.md` — новые решения).
