# Промпт для следующей сессии

Скопировать целиком в новую сессию (лучше с рабочей папкой `D:\onair-lamp`).

---

Проект **OnAir Lamp**: умная розетка Tuya («лампа On air») горит, пока идёт
видеовстреча в Толке, Телемосте или Zoom. Основной проект — `D:\onair-lamp`;
Legacy по лампе больше не развивается и архивом не считается (D-64).

Разработка ведётся в ветке `main`; версия для передачи другим людям — ветка
`Portable`, которая следует за основной (D-65). Релизы — GitHub Releases,
дополнительно портативный zip.

Рабочая папка — `D:\onair-lamp`. Сначала прочитай: `README.md`,
`docs\ARCHITECTURE.md`, `docs\HISTORY.md`, `docs\plan_packaging.md`,
`docs\SUPPORT.md`.

## Технические факты

- `tinytuya 1.21.1`: функции `deviceScan` нет, сканер — `tinytuya.scanner.devices(...)`;
  резерв — пассивное прослушивание UDP 6666/6667/7000 (проверено 16.11.2026),
  адрес подтверждать чтением статуса и сверкой `gwId` с `dev_id`.
- Embeddable-Python: в `python312._pth` обязательны четыре строки —
  `python312.zip`, `.`, `..\vendor`, `..\app\scripts\meetings`; иначе не
  импортируются `plug_control` и `tuya_discovery`.
- Inno Setup 7.1.1: `%LOCALAPPDATA%\Programs\Inno Setup 7\ISCC.exe`; `build.ps1`
  ищет 7, затем 6.
- `build.ps1` скачивает python.org через `curl.exe` (PowerShell 5.1 не всегда
  договаривается о TLS); GitHub-скачивание иногда требует
  `--retry 5 --retry-all-errors`.
- Проверка установщика: `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP-
  /CURRENTUSER /TASKS=autostart`; удаление — `unins000.exe /VERYSILENT`. Перед
  установкой и тестами останавливать другие копии (общий mutex).
- Установщик ставит только в `%LOCALAPPDATA%\Programs\OnAirLamp`
  (`DisableDirPage=yes`, `UsePreviousAppDir=no`); запуск и ярлыки — через
  `wscript.exe`, не прямой `.vbs` (иначе код 193); ярлыки — в папке
  «OnAir Lamp» в меню Пуск.
- Mutex: `Local\LegacyPlugExecutor`, `Local\LegacyPlugTray`,
  `Local\LegacyMeetingsWatcher`, `Local\LegacyPlugSupervisor` — два экземпляра
  одновременно не запустятся; общий для Legacy и нового проекта. Супервизор по
  этим mutex «усыновляет» уже запущенные процессы.
- `profiles.json` лежит рядом со скриптами (`app\scripts\meetings\`), дополняет
  встроенные профили и заменяет профиль по `id`; битый файл не ломает
  наблюдатель. `build.ps1` копирует `*.json` в поставку.
- Тесты: `.venv\Scripts\python.exe -m unittest discover -s tests -v`.
- В dev-копии `.venv\Scripts\pythonw.exe` — обёртка venvlauncher (263 КБ): она
  запускает настоящий `Python312\pythonw.exe` (104 КБ) и ждёт его. Поэтому четыре
  компонента видны как 7 процессов (супервизор, исполнитель и трей — по два).
  Это не дубликаты; `restart-dev.ps1` считает компоненты, а не записи.
- Корень вычисляется как `SCRIPT_DIR.parent.parent`, поэтому в проекте это
  `D:\onair-lamp\app`, данные — `app\data\work\meetings\`, конфиг —
  `app\secrets\tuya_plug.json`. Установка обязана повторять раскладку
  `app\scripts\meetings\…`.
- Устройство: протокол 3.3, переключатель DP 1; адрес задаётся в
  `tuya_plug.json`.
- `scripts\setup-dev.ps1` должен оставаться в UTF-8 **с BOM**, иначе Windows
  PowerShell 5.1 не разбирает кириллицу.
- Отчёт для поддержки: `tools\report_support.py` → zip на рабочем столе; внутри
  `info.txt` и журналы/состояния, без `local_key` и `dev_id`.
- Оценка оставшихся работ по плану — ≈1–1,5 рабочих дня.

## Правила

- Секреты (`local_key`, Access Secret) не печатать, не передавать в модель, логи
  и документы; проверять только факт наличия.
- Не менять ничего в `D:\Legacy` без отдельного разрешения: копия лампы, данные,
  ключ и ярлыки автозапуска оттуда удалены 16.11.2026 (D-64), проект лампы —
  только `D:\onair-lamp`. Не трогать данные и настройки получателей.
- Не устанавливать пакеты и не делать коммиты без разрешения.
- Не выдавать план за результат: «работает» — только после проверки на реальном
  устройстве и живой встрече.
- После значимых изменений обновлять документы проекта (`plan_packaging.md` —
  статусы фаз, `HISTORY.md` — новые решения).
